# День 33. Ассистент поддержки пользователей

Мини-сервис поддержки «Пульт»: отвечает на вопросы о продукте, использует RAG по FAQ и документации,
учитывает данные тикета клиента из CRM. CRM подключена через MCP-сервер, в этой версии это JSON-файл.

Модель: **AITunnel, gpt-5.6-luna**. Ключ вводится скрытым вводом или берётся из `AITUNNEL_API_KEY`.

## Состав

| Путь | Что делает |
|---|---|
| `support/assistant.py` | Ассистент: контекст тикета через MCP, RAG, ответ модели, чат и `--once` |
| `support/service.py` | HTTP-сервис: `POST /api/ask`, `GET /health`, ключ `X-Api-Key` |
| `support/mcp_server.py` | MCP-сервер CRM: `get_ticket`, `get_user`, `list_tickets`. Только чтение |
| `support/mcp_client.py` | MCP-клиент (stdio, JSON-RPC) |
| `support/kb.py` | Индекс FAQ и документации из `docs/` |
| `data/crm.json` | Тестовая CRM: пользователи и тикеты (вымышленные данные) |
| `docs/` | FAQ, авторизация, оплата, документация продукта |
| `test_day33.py` | Проверки на имитации (49 проверок) |
| `run.ps1` | Запуск на ПК: проверки, чат, сервис |

## Запуск

```
.\run.ps1 -Mode test       # проверки
.\run.ps1 -Mode chat       # чат: /ticket T-1001 — выбрать тикет, затем задать вопрос
.\run.ps1 -Mode service    # сервис на http://127.0.0.1:8080
```

Пример вопроса с тикетом: «Почему не работает авторизация?» при `/ticket T-1001`. Ассистент видит, что аккаунт
заблокирован после неверных попыток, и говорит, до какого времени.

## HTTP API

```
POST /api/ask
X-Api-Key: <ключ сервиса>
{"question": "Почему не работает авторизация?", "ticket_id": "T-1001"}
```

Ответ: `answer`, `sources`, `ticket_id`, `mcp_calls`. Коды: 200 — ок, 400 — плохой запрос, 401 — нет ключа,
404 — тикет не найден, 413 — тело больше 16 КБ, 502 — модель недоступна.

## Приватность

- В запрос модели не попадают хеши паролей и полные e-mail (показывается маска `a***@example.com`).
- Данные других пользователей не запрашиваются: ассистент берёт только пользователя из открытого тикета.
- Сервис слушает только 127.0.0.1. Для доступа извне ставьте перед ним HTTPS-прокси и аутентификацию.

## Что проверено

На имитации: протокол MCP и инструменты, маскирование и отсутствие секретов, поиск по FAQ, ответ с учётом тикета,
приватность в запросе модели, HTTP-коды и ограничения, CLI. Итог 49 из 49.

Только на вашей стороне: ответы настоящей gpt-5.6-luna, работа на вашей реальной CRM, развёртывание за HTTPS.

## Ограничения

- CRM — JSON-файл. Для настоящей CRM замените `support/mcp_server.py` на сервер, который ходит в API CRM, сохранив имена инструментов.
- Интерфейса в браузере нет: сервис отдаёт JSON. Для страницы чата нужен отдельный фронтенд.
- Если ответа нет в FAQ и тикете, ассистент пишет, что передаёт вопрос оператору, но сам оператора не вызывает.
